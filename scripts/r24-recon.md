# Frame loop & presentation (R3F loop, useFrame priority graph, EffectComposer sizing/render, DPR governor ladder, floating-origin rebase, main-thread work inside/adjacent to the frame) — tree at 3592656 (R21)

The loop is R3F 9.6.1 frameloop="always"; nothing demand-renders. The ONLY scene render is the vendored FlyEffectComposer's useFrame at priority 1 (composer.render → RenderPass → renderer.render, which also runs the shadow pass and three-tile's LOD walk inside it); R3F auto-render is disabled because priority>0 subscribers exist. Simulation is at -50 (FlyScene) and every world layer runs between -49 and 0, so world layers are internally consistent per frame. The two genuine one-frame lags are OUTSIDE that graph: the DOM LabelCanvas draws on its own rAF registered before the GL loop (projects with last frame's camera matrices → labels/reticle swim vs planes when turning), and drei Clouds' child useFrame runs before CloudField's parent frame (stale puff/camera matrices). DPR rungs resize the drawing buffer synchronously in React's commit but the composer resizes a passive effect later (1–2 frames at stale internal resolution + RT reallocation hitch). Stutter sources are all main-thread: three-tile's skirt builder (edge sort per tile, unpatched here), first-draw uploads inside the render, raycast-based DEM sampling (~3–4 ms/frame budgets), PMREM re-bakes (8 per twilight), rebase traversal. No fixed timestep, no interpolation, no temporal AA; governor targets ≤60 fps. Health: correct but hitchy; visuals limited by single-frame SMAA + Bayer screen-door fades.

## Pain points

### [high] FL-01 HUD LabelCanvas runs one frame behind the GL frame (its own rAF is registered before the R3F loop)  (code-read)
**Symptom:** Aircraft labels, the lock reticle, hover ring and tap hit-test all trail their planes by one frame — at 60 fps and ~60°/s yaw that is ~1° ≈ 30 px of swim on a 1920-wide canvas; reads as the HUD 'tearing' away from the 3D world during turns and as labels floating off warped-in planes on the cut frame.
**Evidence:**

- components/fly/hud/LabelCanvas.jsx:341 — `_v.set(wx, wy, wz).project(camera);` (uses camera.matrixWorldInverse/projectionMatrix)
- components/fly/hud/LabelCanvas.jsx:536-543 — `draw();` started in a useEffect with deps `[runtime]` (once, at FlyMode mount)
- components/fly/FlyMode.jsx:270 vs :298 — `{spawn && <FlyCanvas .../>}` (GL mounts only after geolocation resolves) while `<LabelCanvas>` is mounted unconditionally from the first render
- node_modules/@react-three/fiber/dist/react-three-fiber.esm.js:62-102 — the R3F root is created/rendered inside Canvas's layout effect (after spawn), i.e. its loop rAF is registered AFTER LabelCanvas's
- node_modules/@react-three/fiber/dist/events-b389eeca.esm.js:16071-16072 — `function loop(timestamp) { frame = requestAnimationFrame(loop);` (same re-register-first pattern)
- node_modules/three/build/three.module.js:17633 — `if ( camera.parent === null && camera.matrixWorldAutoUpdate === true ) camera.updateMatrixWorld();` — camera matrices are only refreshed inside renderer.render (priority 1)
**Mechanism:** rAF callbacks run in registration order; both loops re-register as their first statement, so whichever registered first at boot stays first. The overlay is a consistent picture of frame N-1 composited over GL frame N.
**Fix:** Drive the label draw from the GL frame: register it with R3F's `addAfterEffect` (runs after all roots render) or a useFrame at priority 2 inside the canvas that calls the draw closure via runtime; alternatively have FlyScene publish `camera.matrixWorldInverse`/`projectionMatrix` after calling `camera.updateMatrixWorld()` at the end of -50 and project with those. Keep phone 30 Hz frameStep logic.
**Cost/risk:** Zero GPU cost. Touches the verify-inspect/labels harness contract only if they rely on LabelCanvas's own rAF; the 2D canvas draw moves into the same task as the GL frame (adds its ~0.5–1 ms to the frame's main-thread budget instead of a separate rAF slot).

**Evidence:**

### [high] FL-04 Simulation and camera are integrated on render dt (clamped at 50 ms) with no fixed step or interpolation; governor targets ≤60 fps even on 120/144 Hz displays  (code-read)
**Symptom:** Judder on high-refresh monitors (frames alternate 1 and 2 vblanks while the governor reports 'healthy'); every dropped frame is a visible jump; long frames slow the world down (time dilation) instead of catching up; traffic keeps wall-clock time while the player world slows, so relative motion glitches during hitches.
**Evidence:**
- components/fly/FlyScene.jsx:1052 — `const dt = Math.min(delta, 0.05);` and :1216 `flight.step(dt, apCmd ?? cmd);`
- lib/fly/flight-model.js:266-268 — `this.pos.x += Math.sin(this.heading) * vxz * k * dt; ... this.pos.y += vy * dt;` (explicit Euler on render dt)
- lib/fly/chase-camera.js:142 — `const l = 1 - Math.exp(-CAMERA.posLambda * dt);` (exp damping on render dt — frame-rate independent but still per-render-frame)
- lib/fly/perf-governor.js:205 — `g.targetFps = Math.min(60, best);` and :216/235 downFrac/upFrac gate against that target
- components/fly/TrafficLayer.jsx:172-174 — `setNavTime(performance.now() / 1000); const items = traffic.update(performance.now() / 1000, flight.pos);` (wall clock, not frame dt)
- grep for fixed-step/interpolation in flight-model/chase-camera/traffic-engine → no hits
**Mechanism:** Render pose == sim pose; there is no accumulator, so motion smoothness equals frame pacing. On a 144 Hz display running at ~100 fps the governor never steps (100 > 0.97×60) yet presentation alternates 7/14 ms intervals. The 50 ms clamp converts any stall into a world slow-down, while traffic dead-reckoning and clock-driven layers keep real time.
**Fix:** Fixed-step sim (e.g. 120 Hz accumulator, max N substeps) with an interpolated render pose for flight/camera; keep `flight.pos` as the authoritative sim state and publish an interpolated `renderPos/renderQuat` that PlayerPlane/-30, camera and contrail read. Governor: target the estimated refresh (or 60 when refresh ≥ 120 and the user prefers), add a p95/long-frame term so stutter (not just mean fps) can step the ladder.
**Cost/risk:** CPU-neutral. Breaks the implicit contract that every layer reads `flight.pos` as the render pose (PlayerPlane.jsx:74, Contrail.jsx:146-148, PlayerGroundShadow, crash detector) and the harness poses that pin `flight.pos`; must be done as an opt-in flag with the pose seam explicit.

**Mechanism:** Each blend step re-renders an equirect blend and re-runs PMREMGenerator.fromEquirectangular (multiple passes over a 256² cube + mips) synchronously in a microtask; the frame that follows absorbs the GPU queue stall.

**Cost/risk:** A shader-side blend adds a second cube sample to every MeshStandardMaterial in satellite (cache-key move for tiles/traffic/buildings); the cheap alternative (fewer, smaller bakes) keeps keys but coarsens the dusk ramp certified by verify-dusk.

### [medium] FL-11 No temporal accumulation anywhere: single-frame SMAA, Bayer-4 screen-door fades, compositor bilinear upscale at reduced DPR  (code-read)
**Symptom:** Crawling/shimmer on the 2400–3000 m building fade band and the skyline dither, sparkle on thin geometry (tracers, poles, windows), and a soft image at DPR 1.0–1.25 rungs with an abrupt sharpness change at each step.
**Evidence:**
- components/fly/Effects.jsx:238-242 — `list.push({ id: 'smaa', el: () => <SMAA key="smaa" /> ...` (only AA; `multisampling={0}` at :460)
- lib/fly/toy-world/world-bend.js:1388-1392, 1404-1406, 1448 — 'A screen-door DITHER is the only …', `float wbBayer4( vec2 p )`, `uniform float uSatBldgFade` (per-pixel discard, no frame index)
- lib/fly/fly-constants.js:1245-1250 — SAT_BLDG_FADE 2400→3000 m AGL
- grep for TAA/jitter/velocity/accumulat in components/fly, lib/fly → only unrelated hits (e.g. juice accumulator)

**Fix:** Cheapest: frame-indexed blue-noise/IGN for the fades (temporal dither) plus SMAA — reads as film grain rather than screen-door. Fuller: a TAA pass (camera jitter in the RenderPass + reprojection using the previous frame's view-projection; traffic/instanced movers need velocity or a confidence fallback) which also enables render-scale upscaling (TAAU) as the governor's resolution knob instead of canvas DPR.

# Terrain streaming & LOD — three-tile 0.12.1 (npm, NOT vendored at 3592656) behind lib/fly/terrain-engine.js + lib/fly/tile-sources.js; tile material patch (world-bend fade + hillshade/micro/quilt) in FlyScene/world-bend.js; SatTintLayer + AerialPerspective as the tile-adjacent overlays

At this commit the terrain is stock three-tile 0.12.1 from node_modules (readable Vite ESM bundle, inline Blob-URL workers), wrapped by TerrainEngine and mounted inside a floating-origin worldRoot. Esri World Imagery (z16, z17 on high) + Esri Terrain3D LERC DEM (z15, cropped for z16/17) feed a quadtree that three drives from projectObject every render. LERC decode + Martini run in a 5-worker pool; imagery loads via HTMLImageElement; skirts are built on the MAIN thread per tile. LOD swaps are atomic (no hole, no z-fight) but hard pops with no fade, gated on the slowest of four children. The quadtree traverses every frame (the 50 ms updateInterval is dead: Timer.reset never zeroes _elapsed), freezes entirely when >=6 downloads are in flight, refines only in-frustum tiles but MERGES any subdivided tile that leaves the frustum with zero hysteresis, so every bank/yaw re-streams the near field and pops in at the screen edge. Tile normals are flat-per-face (last-writer), lit three times (PBR sun, hillshade, baked imagery). DEM refinement snaps geometry and every AGL-keyed effect (groundElev is written raw). Health: functional and certified on draws/tris, but structurally incapable of smooth streaming without vendoring and patching ~6 small sites in the Tile/loader/geometry code. Nothing here was rendered or measured (tile hosts 403); all magnitudes are code-read or taken from the repo's own later-round measurements.

## Pain points

### [critical] T1 Out-of-frustum merge + in-frustum-only refine with zero hysteresis: every yaw/bank re-streams the near field and pops in at the screen edge  (code-read)
**Symptom:** Turning or banking: terrain just outside the old view arrives blurry and sharpens in staged pops (z10->z17, ~6 quad swaps, each landing 4 tiles at once); the field behind you silently collapses to coarse tiles and must be re-downloaded/rebuilt when you turn back. At a fixed distance ratio near the threshold, a tile can flip refine<->merge repeatedly (four downloads discarded per cycle).
**Evidence:**
- node_modules/three-tile/dist/index.js:225 — `return this.inFrustum ? t * 0.8 : t * 5;` (distance ratio is ×6.25 harsher the moment a tile leaves the frustum)
- node_modules/three-tile/dist/index.js:214-218 — `_LODEvaluate`: refine if `isLeaf && z < maxLevel && n <= r`, merge if `!isLeaf && z >= minLevel && n > r` — SAME threshold both ways, no hysteresis
- node_modules/three-tile/dist/index.js:174-178 — `LOD(e)`: refine requires `this.inFrustum`; merge (`s === 2 && this.subTiles && this._removeSubTiles(e)`) has no frustum requirement
- node_modules/three-tile/dist/index.js:191 — only `!_inFrustum && _model && isLeaf` tiles are skipped; non-leaf out-of-frustum tiles are evaluated and merge one level per traversal
- node_modules/three-tile/dist/index.js:280-286 — `_removeSubTiles` downloads a NEW parent model (`new Z(); await t.update(this,o)`) then `unloadSubTiles()` (disposes all descendant textures/geometry)
- lib/fly/fly-constants.js:2103-2106 — `lruBudgetBytes: 140MB` / `viewDistanceM: 250000` — grep shows NEITHER is consumed anywhere outside the constants file: residency is bounded ONLY by this merge policy
**Mechanism:** Three calls TileMap.update from projectObject; Tile._update evaluates every node. Frustum exit multiplies the LOD ratio by 5 so any subdivided tile behind/beside the camera immediately satisfies the merge rule; merging fetches the parent again (imagery + LERC), rebuilds its geometry (skirt on main thread), uploads a new texture, and disposes the children. On re-entry the ratio drops ×6.25 and the quad re-refines from whatever level survived (typically the tile that still intersects the frustum, ~z10-11 near the player). Chase-camera yaw therefore drives a continuous merge/refine wave whose cost is download+decode+skirt+upload+dispose per tile, and whose visual is staged pop-in at the leading screen edge.
**Fix:** Vendor three-tile (copy dist/index.js; ~2k readable lines) and patch Tile: (1) evaluate MERGE with the in-frustum formula only (drop the ×5) and add hysteresis (merge when ratio > threshold×1.6, refine when <= threshold); (2) never merge on frustum exit alone — leave loaded leaves resident and let three's per-mesh frustum culling skip their draws; (3) add the missing residency budget: collapse only tiles farther than K× their own refine distance or when a byte LRU (wire TILES.lruBudgetBytes) is exceeded; (4) refine inside an inflated prefetch frustum (projection scaled ~1.4× horizontally, or yaw-rate-led) so pop-in lands off-screen. Keep TILES.lodThresholdByTier semantics (0.86 high) so the Owens 261 draw gate is unaffected — culled resident tiles are not draws.
**Cost/risk:** GPU: ~0 extra draws (resident-but-culled tiles are not submitted); VRAM: resident field grows — a 256² sRGB tile with mips is ~340 KB, so 500 resident tiles ~170 MB against PERF_BUDGET.textureBytes 300 MB — the byte LRU is mandatory on medium/phone. Network drops sharply. Touches the frozen verify-sat-depth/aerial draw numbers only if culling misbehaves (see T12). Requires the vendor move (package.json overrides + transpilePackages already reference the npm name).

### [critical] T2 Skirt builder (getBoundaryEdges) runs on the main thread per tile after the worker returns — a stall proportional to triangle count  (code-read)
**Symptom:** Micro-stutter/hitches while tiles land, worst when several tiles finish in the same task turn (post-warp descent, banking into fresh terrain, mountainous z15/z16 tiles).
**Evidence:**
- node_modules/three-tile/dist/index.js:1157-1163 — LERC `doLoad`: `a = (await this._workerPool.postMessage(o)).data; return new A().setAttributes(a, r);` (worker returns attributes; skirts are built in the main-thread continuation)
- node_modules/three-tile/dist/index.js:660-662 — `setAttributes(e, t)`: `r = t === 0 ? 0 : 2e5 / t / t; r > 0 && (e = Re(e.attributes, e.indices, r))`
- node_modules/three-tile/dist/index.js:623-635 — `We(i)`: pushes 3 two-element arrays per triangle, `e.sort(...)` with a comparator, then dedups — O(T log T) allocations+sort per tile
- node_modules/three-tile/dist/index.js:594-621 — `Re` then concatenates position/texcoord/normal with `E(...)` (full typed-array copies)
- CLAUDE.md top notice (describes the LATER R22.1 tree, but it patched this exact upstream function): 'three-tile's getBoundaryEdges skirt builder on the main thread (67% of stall samples) … worst 87.5→29 ms'
**Mechanism:** Martini at error 11 m (z15) yields tens of thousands of triangles in relief; z16 tiles (cropped z15 DEM, error 1 m) approach the full 128² grid (~32k tris). For each, the skirt pass allocates ~3T small arrays, sorts them with a JS comparator, dedups, copies all attributes twice, and builds BufferAttributes — 5–30 ms per tile on a mid CPU, executed in a promise continuation that can chain several tiles into one long frame.
**Fix:** Move skirt generation into the LERC worker message (the worker already holds positions/indices), and replace the edge-sort with an O(V) boundary scan: Martini vertices carry grid coords, boundary = x==0||x==max||y==0||y==max (or |pos.x|==0.5/|pos.y|==0.5). Emit final position/uv/normal/index arrays as transferables; main thread does only `new BufferAttribute`. Output is identical by construction (the R22.1 note claims the same). Requires editing the inline worker blob string in the vendored bundle (or forking three-tile src).
**Cost/risk:** No GPU change; worker CPU trivial; one-time vendoring. Risk: the worker string is minified — keep a readable source next to it and a build step, or hand-patch carefully.

### [high] T3 Quadtree traversal runs EVERY frame (updateInterval is dead), allocates per tile, and freezes wholesale when ≥6 downloads are in flight  (code-read)
**Symptom:** Steady per-frame CPU + minor-GC pressure (micro-stutter), and bursty LOD behaviour: during streaming the tree stops re-evaluating frustum/merge state, then catches up in a burst when downloads drain.
**Evidence:**
- node_modules/three-tile/dist/index.js:1812-1814 — `TileMap.update`: `this._mapTimer.update(), this._mapTimer.getElapsed() > this.updateInterval / 1e3 && (this.rootTile.update(...), ..., this._mapTimer.reset())`
- node_modules/three-tile/dist/index.js:1335 — `Timer.reset()` sets only `_currentTime`; `update()` (:1355) does `this._elapsed += this._delta` — `_elapsed` is never zeroed, so after 50 ms of uptime the guard is permanently true
- node_modules/three-tile/dist/index.js:100-103 — `get BBox()` allocates `new Box3(new Vector3, new Vector3)` per tile per traversal; :191 `q.intersectsBox(this.BBox)`
- node_modules/three-tile/dist/index.js:186 — `if (!(t.downloadingThreads + 4 >= t.maxThreads || this.loadState === "loading"))` — with TILES.maxThreads 10 (fly-constants.js:2110) the ENTIRE tree update is skipped once 6 loads are pending
- node_modules/three-tile/dist/index.js:223 — `console.assert(this._sizeInWorld > 10)` per tile per traversal (dev guard in lib/fly/terrain-engine.js:29-40 only hides the call from Next instrumentation)
- FLY_TOYWORLD_REWORK.md:296-297 — the assert flood was measured at '~100k+/s' (consistent with ~1000+ tiles × every frame)
**Mechanism:** three's projectObject calls object.update(camera) for isLOD objects each render (node_modules/three/src/renderers/WebGLRenderer.js:1843-1845). Because the timer bug makes the interval guard always pass, every frame walks every Tile (frustum AABB alloc+test, LOD ratio, shadow sync, closure per child). Separately, the +4 freeze rule means one refine batch (4 loads) plus a second already halts all LOD decisions — including merges and frustum flags — until the queue drains.
**Fix:** Vendored one-liners: zero `_elapsed` in Timer.reset (restores the 20 Hz cadence; or set map.updateInterval ~66 ms after the fix), cache a per-tile world AABB invalidated by a rebase epoch (rebase is the only matrixWorld change), and replace the global freeze with a per-tile 'skip REFINE when saturated' so frustum/merge evaluation keeps running. Optionally time-slice the traversal (N tiles per frame).
**Cost/risk:** Zero GPU cost; small CPU/GC win. Risk: LOD reacts at 20 Hz instead of per-frame — imperceptible (the loads take 100s of ms anyway).

### [high] T4 LOD swap is an atomic hard pop: no crossfade, all-four-or-nothing children, and 4 texture+geometry uploads land on one frame  (code-read)
**Symptom:** Visible 'pop' when a quad refines (texture sharpness AND relief snap — Martini error 91 m at z13 vs 11 m at z15 — silhouettes/ridges jump); one slow Esri tile keeps a whole quad blurry while neighbours are sharp ('patchy'); the frame the swap lands pays 4 texImage2D+mipmap+buffer uploads.
**Evidence:**
- node_modules/three-tile/dist/index.js:257-271 — `_loadSubTiles`: children created with `_loadState='loading'` but NOT added; `await Promise.all(a)` then `this.add(...o)` ... `this.unloadModel()` in one synchronous block (no frame where neither is drawn, no frame where both are)
- node_modules/three-tile/dist/index.js:280-286 — `_removeSubTiles`: same atomic pattern for merges
- node_modules/three-tile/dist/index.js:1044-1049 — imagery becomes `new Texture(img)` (HTMLImageElement); three uploads lazily on first draw (WebGLTextures texImage2D :1383), so the first frame after the swap does all four uploads + `generateMipmap`
- node_modules/three-tile/dist/index.js:430-441 — Martini error table `7000·(1−z/17)³` → z13 ≈ 91 m, z15 ≈ 11 m, z16 ≈ 1 m: the surface itself moves at refine
- components/fly/FlyScene.jsx:777-793 — `onTileMaterial` runs on 'tile-loaded', i.e. after the swap; the patched program is prewarmed so no compile hitch, but there is no birth uniform
**Mechanism:** three-tile has no transition state: a tile is either the parent mesh or the four child meshes, swapped inside a promise continuation between frames. The only mitigation today is the 'hold until sharp' arrival mask at warps; in free flight every refine/merge is a hard cut plus an upload spike.
**Fix:** Vendored `_loadSubTiles`/`_removeSubTiles`: (a) pre-upload before the swap — call `renderer.initTexture(map)` (and `attributes` upload via a hidden draw or `gl.compile`-style prepass) in the frames before add, so the swap frame is upload-free; (b) a short dithered cross-dissolve (~200–300 ms): keep the parent drawn while children fade in with the existing Bayer screen-door idiom (SAT_BLDG_FADE) via a per-material `uBirth` uniform in the hillshade patch — this is a shader-text change → bump the FINAL tile key 'world-bend-fade-hill-r19' and the PREWARM registry; (c) cheaper alternative with no double draw: children start sampling the parent's texture through a clip-UV transform and blend to their own map over the same window (parent map retained N frames). Geometry snap cannot be morphed (Martini topologies differ) — the dither hides it.
**Cost/risk:** (b) +1 parent draw per in-flight quad for the fade window (≤5 draws transient, more at boot — keep boot dither-free) and one cache-key move (toy + satellite tile programs recompile; toy must stay pixel-identical via a 0-gated uniform). (c) ~0 draws, ~1 extra texture unit on the tile program and parent-texture retention. (a) is free.

### [high] T6 Terrain normals are flat-per-face (last-writer) and the surface is lit three times (PBR sun/hemi + hillshade + baked imagery shading) → faceted, over-shaded relief with seams at LOD boundaries  (code-read)
**Symptom:** Low-AGL relief reads as a faceted low-poly mesh under the sun; hillshade shows triangle facets and a visible shading discontinuity along tile edges where a z13 tile meets a z15 tile; slopes are darker than the photo implies (imagery already contains the capture sun).
**Evidence:**
- node_modules/three-tile/dist/index.js:474-481 — `ce(i,e)`: per triangle `t[n] = t[s] = t[o] = g * w` — each shared vertex simply takes the LAST face's normal (no accumulation/normalize) — identical code in both worker blobs
- node_modules/three-tile/dist/index.js:301-305 — `TileMaterial extends MeshStandardMaterial` ({transparent:false, side:FrontSide}) — full PBR lighting from the scene's sun + hemi (+ scene.environment IBL in satellite)
- lib/fly/toy-world/world-bend.js:1114-1122 — `vHill = clamp(dot(normalize(transformedNormal), ...uHillDir))` — hillshade also reads the same faceted normal
- lib/fly/toy-world/world-bend.js:1133-1143 — `shaded = ... lit × ao ...; diffuseColor.rgb = mix(diffuseColor.rgb, shaded, uHillStrength)` multiplies on top of the PBR result (strength 0.55, aoByTier 0.34)
- node_modules/three-tile/dist/index.js:649 — skirt normals are hard-coded `(0,0,1)` (world up after the −90° rotation): vertical walls lit as flat ground
**Mechanism:** Martini triangulates a 2^n+1 grid into long slivers on gentle slopes; with last-writer normals every vertex belongs to one arbitrary triangle, so Gouraud interpolation cannot smooth them. Neighbouring tiles at different Martini errors produce different normal fields at the shared edge. **Fix:** In the worker: compute normals from the FULL decoded DEM grid (central differences at every grid sample, before Martini decimation) and look them up per Martini vertex — smooth, cheap (O(N²) on 257² once per tile), and continuous across LOD boundaries because both levels sample the same DEM field; give skirt vertices their edge vertex's normal. Consider keeping `uHillStrength` as the ONLY slope term and letting the sun only drive its direction (setHillDir already exists).
**Cost/risk:** Worker CPU +~1 ms per tile; GPU fragment cost DROPS if PBR is dropped (terrain is the largest fill-rate consumer). Changes the certified satellite look (verify-sat-depth mean-Δ gates, hillshade A/B) — a taste checkpoint. Toy pixel-identity must be preserved via the 0-gated uniforms.

# World-bend shader + vector chunk pipeline (toy world, satellite buildings, skyline, roads, veg/parcel homes; vector-tile worker) — commit 3592656 (R21 merge)

One Comlink worker per engine (five instances of the same vector-tile.worker.js) fetches OpenFreeMap MVT tiles (persistent Cache API, raw bytes), tessellates with earcut + ribbon/box extrusion into transferable typed arrays, and four main-thread engines (ToyWorldEngine, SatBuildingEngine, SatSkylineEngine, SatRoadEngine; SatVegEngine owns no GPU objects) drape them on the three-tile DEM and upload one merged mesh per chunk. Every ground material is patched by one of 15 FINAL world-bend variants (d²·k vertex drop, per-vertex for tiles/land/roads/water, per-anchor for rigid buildings/skyline/instanced props), all keyed in the registry and pre-warmed at boot. Health: streaming correctness is good after R21 (bend margins, capped heals, retry TTLs), but (1) the worker emits exactly-degenerate wall/parapet/crown quads at every ring closure because @mapbox/vector-tile closes rings with a clone of ring[0] and nothing dedupes; (2) chunks still appear/vanish in ONE frame — no birth fade or crossfade exists anywhere in this subsystem; (3) finalize is per-chunk, not time-budgeted (sat/skyline/road); (4) mid-flight recompile storms remain (dusk HDRI resolution mismatch; shadow-rig flips on tier steps; style flips) that the harness fleet is structurally blind to; (5) DoubleSide + `discard` on all building programs costs fragment throughput. Nothing here was runnable (tile hosts 403); all claims are code-read unless marked.
