## 1. Phase 1 — Rarity DB + exact-first scoring + archetype classification (A7)

- **[lib/warbirds.js](lib/warbirds.js)** — plain ESM, **zero imports** so the
  node audit harness dynamically imports it exactly like `assets.js`. Three
  lock-step exports over the same 170 codes: `WARBIRD_TYPE_RARITY`
  (exact CODE → bonus), `WARBIRD_ARCHETYPE` (exact CODE → archetype string),
  `WARBIRD_TYPES` (Set for contracts). Every code is a real ICAO doc8643
  designator (`ME09`, `CORS`, `HUCO`, `CONI`, `TRIM`, `G2GL`, `N320`…).
- **`lib/rarity.js`** — `CLASSIFICATION_RARITY` gains the four archetype bases
  (`warbird-prop 45, warbird-jet 45, warbird-heavy 50, classic-transport 40`);
  `calculateRarity` now does the **exact warbird lookup FIRST and, on a hit,
  adds the audited bonus and short-circuits the substring loop entirely.** WHY:
  the legacy loop *stacks every matching substring* (`B29` would also catch key
  `B2` for +60), so exact keys must never enter substring space or their scores
  compound. Non-warbird codes miss the table and fall through to the original
  loop byte-for-byte — **empty `typeCode` included** (falsy guard → else branch →
  substring over `''` → no match, identical to pre-R14). Tier math: base+bonus
  lands the marquee list at Legendary+ (≥85), ultra-rares 95–97 (headroom under
  the AF1 stack + the `Math.min(…,100)` clamp). Histogram: common 12 · uncommon
  50 · rare 26 · epic 32 · legendary 41 · mythic 9.
- **Worker** (`lib/workers/aircraft-processor.worker.js`) — an **inlined synced
  copy** of `WARBIRD_ARCHETYPE` (the worker runs standalone, cannot import), an
  exact check at the TOP of `getAircraftIconType` (returns the mapped archetype
  before any substring list), and the four archetypes **appended** to
  `FLY_ARCHETYPES` at 9–12. `militaryTypes` was deliberately **not** touched:
  warbirds are NOT `military` iconType (no red tint, no military auto-ping, no
  spot-military miscount) — they ping via the Legendary tier gate instead. The
  inline copy is kept in sync by the D6 gate, not by imports.

## 7. Lessons

1. **Substring tables need an exact-first escape hatch.** The pre-R14 rarity
   loop summed *every* matching substring; adding real 2–4-char warbird codes
   into that space would have compounded scores unpredictably (`B29`→+`B2`,
   `DC7`→…). The fix isn't a bigger table — it's an exact map checked first that
   short-circuits the fuzzy loop, with a gate proving the fuzzy path is
   byte-unchanged for every non-warbird code.
2. **Both paired verifiers can reject the same row for opposite ownership
   reasons — the merge must arbitrate.** A code living in two source lists got
   double-rejected ("not mine — it's the other list's") and would have silently
   vanished. When two adversarial verifiers each own a partition, the merge step
   is the only place that sees the union; it must reconcile cross-partition
   drops, not treat two rejections as consensus.
3. **Scouts should report honest fallbacks, not forced picks.** "poly.pizza has
   no era-correct warbird" is a *usable* finding: it routes three archetypes to
   purpose-built primitives (which shipped clean) instead of hanging wrong-era
   models on B-17s. A scout that always returns a "match" launders its own
   uncertainty into the product.
4. **Append-only index contracts want a source-parse gate, not trust.** Four
   files must agree on archetype order 0–12 and the worker keeps a hand-inlined
   copy of a 170-row map; the only durable guarantee is a harness that parses
   all of them as text and diffs — which caught nothing this round precisely
   because everyone respected it, and would have caught divergence instantly.
5. **A tightened gate is a feature when it's measured.** Dropping sat-depth
   375→261 re-anchors the alarm to reality (measured 245 + headroom) so the next
   accidental +100-draw regression trips it instead of hiding under slack.
